# v1.5.0 — IAM Identity Center, one-click console, and setup wizard

Adds AWS accounts reached through **IAM Identity Center** (federated to Entra ID) alongside the
existing SAML/ADFS profiles, one-click AWS console sign-in, and a guided setup wizard.

Existing SAML profiles are unaffected and need no migration.

---

## ✨ IAM Identity Center

- Browser sign-in with PKCE, then silent renewal. No Entra app registration, no admin rights.
- **Bulk import** — sign in once, pick which accounts and permission sets become profiles.
- **One session per organization**: eight profiles produce one sign-in prompt, not eight.
- Credentials land in `~/.aws/credentials` exactly as SAML profiles do.
- Auto refresh never opens a browser. When a session needs a human it prompts and waits, and that
  is not counted as a failure.

## 🔐 One-click AWS console

- A button on every profile, plus an **AWS Console** tray submenu. Same for both account types.
- Refreshes stale credentials first, showing progress above the taskbar while it does.
- **Several accounts signed in at once** — no more "You must first log out".
- Opens in your browser (choose which), or an in-app window per profile.

## 🧭 Setup wizard

- Asks which sign-in method you use first, then shows only the steps that apply.
- **Bulk SAML import**, matching the Identity Center importer.
- **Organization configuration files** — an admin exports a `.json` from
  *Settings → General* and shares it; new users load it and everything is prefilled. Contains no
  secrets, and can be imported at any time, not just during setup.

## 🔒 Security

- **The master password now covers Identity Center.** It encrypts stored sessions and locks the
  app on restart, and is offered for either account type rather than SAML only.
- While locked, the tray is disabled and nothing auto-refreshes.
- **"Forget master password" now signs the browser out** of the identity provider, so getting AWS
  credentials again requires re-authenticating.
- SSO tokens moved to a `safeStorage`-encrypted file — Keytar's 2560-byte limit had been silently
  failing to store them.
- Console sign-in tokens are built and used only in the main process; never sent to the renderer.
- `npm audit` back to **0 vulnerabilities**.

## ⚡ Faster startup

Cold start **~15.1s → ~1.9s**. The terminal is now prepared in the background shortly after
launch instead of blocking it.

## 🆕 What's new after updating

The first launch on a new version shows that version's release notes. Nothing appears when a
release has none.

---

## 🐛 Fixes

- Signing in with the wrong Identity Center account is recoverable — every retry used to replay
  the same error until the app was reset.
- Opening the AWS console no longer dead-ends on an HTTP 400 from multi-session opt-in.
- Setup wizard: setting a master password no longer skips the next step, and "Skip setup" now
  actually closes setup.
- The wizard stops asking about the organization file once you have answered.
- Identity Center session length is labelled correctly: it controls refresh frequency, while the
  session length itself is set by your administrator.
- Renaming a profile's credentials section moves it in `~/.aws/credentials` instead of stranding
  the credentials.
- Settings changed elsewhere in the app are no longer silently reverted.
- Account display names apply immediately.
- No live countdown for credentials that do not exist.
- Restoring a config clears credential sections for profiles that no longer exist.
- Settings is tabbed instead of one long scroll; the splash screen can be dragged; secondary
  windows use the app icon.

## Upgrading

No action required — profiles, settings and stored credentials carry over. New defaults (console
opens in your browser, launch at startup on) apply to fresh installs only.
